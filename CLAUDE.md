# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Workspace

pnpm + Turborepo monorepo. `packageManager: pnpm@9.15.9`, Node `>=20`. Workspaces are `apps/*` and `packages/*`.

- **apps/user** — Next.js 16 app (RSC, `next dev --turbopack`).
- **apps/admin** — Vite + React 19 SPA (no RSC).
- **apps/auth** — Keycloakify v11 theme (Vite + React 19) themed `metronome`. The dev script also boots a local Keycloak server (see below).
- **packages/ui** — `@metronome/ui`, the shadcn-style component library shared by all apps. Exports `./components/*`, `./lib/*`, `./hooks/*`, `./globals.css`, and `./postcss.config`. shadcn style is `radix-nova`, base color `neutral`, icon library `phosphor`.
- **packages/ts-cfg** — `@metronome/ts-cfg` shared `tsconfig` presets: `base.json`, `nextjs.json`, `vite.json`, `react-library.json`. The base is strict + `noUncheckedIndexedAccess`. Every app/package extends one of these.

## Common commands

Run from the repo root:

```bash
pnpm dev                  # turbo dev — runs all apps in parallel (persistent)
pnpm build                # turbo build
pnpm typecheck            # turbo typecheck (per-package `tsc --noEmit`)
pnpm lint                 # biome lint .
pnpm format               # biome format --write .
pnpm check                # biome check --write . (lint + format + organize imports)
pnpm knip                 # find unused exports/files/deps
```

Per-app dev (run inside the app dir, or via `pnpm --filter <name> dev`):

- `user`: `next dev --turbopack`
- `admin`: `vite`
- `auth`: see Keycloak dev workflow below. Use `pnpm dev:vite` for fast theme iteration without booting Keycloak.

## Adding shadcn components

Components live in `packages/ui/src/components/` and are imported as `@metronome/ui/components/<name>`. To add one, run shadcn against an app (it reads that app's `components.json` but writes to `packages/ui` via aliases):

```bash
pnpm dlx shadcn@latest add button -c apps/user
```

The `apps/auth` and `apps/admin` `components.json` configs work the same way. Per-app `@/*` aliases point at the app's own root (`apps/user/`) or `src/` (`apps/admin/src/`, `apps/auth/src/`); cross-package imports always go through `@metronome/ui/...`.

## Keycloak dev workflow

`apps/auth/package.json` `dev` is a one-shot script that:

1. Starts the `postgres` service from `infrastructure/docker-compose.yml` and waits for it.
2. Runs `keycloakify build` to compile the theme into `infrastructure/keycloak/providers/`.
3. Copies `.keycloakify/realm-kc-26.json` into `infrastructure/keycloak/data/import/` and the keycloakify logging jar into the `providers/` dir.
4. In the background, polls `http://localhost:8080` and once Keycloak is up uses `kcadm.sh` to set the master realm's `loginTheme=metronome`.
5. Foreground: launches Keycloak via `infrastructure/keycloak/bin/kc.sh start-dev --import-realm` with bootstrap admin `admin/admin`.

Implications:

- A local Keycloak distribution is expected at `infrastructure/keycloak/` (with `bin/`, `lib/`, `data/`, `providers/`, etc.). It is gitignored.
- Theme changes require either re-running `pnpm dev` or `pnpm build-keycloak-theme` and restarting Keycloak. For pure UI work on the React pages, prefer `pnpm dev:vite` (the keycloakify dev harness with mocked `kcContext`).
- `apps/auth/src/login/KcPage.tsx` is the page-id router — every Freemarker page (`*.ftl`) maps to a lazy-imported component under `src/login/pages/`. Each page also has a co-located `*.stories.tsx` for the keycloakify storybook (`pnpm storybook`).
- `src/kc.gen.tsx` is generated by keycloakify; treat as generated.

## Tooling pipeline

- **Biome 2** (`biome.json`) is the only formatter/linter. Style: 2-space, 80 cols, double quotes (JSX too), semicolons `asNeeded`, trailing commas `es5`, arrow parens always. CSS modules + Tailwind directives are enabled.
  - Per-folder overrides relax rules for `packages/ui/src/components/**` (shadcn primitives — a11y/security exceptions) and `apps/auth/**` (keycloakify-generated code — many `correctness`/`a11y`/`suspicious` rules disabled). Do not re-enable these blanket rules; if you need to lint a new folder strictly, add a more specific override.
  - `useSortedClasses` (nursery) is on for `className`, `cn`, `cva`, `clsx`, `tw`. Run `pnpm check` to auto-fix.
- **Lefthook** (`lefthook.yml`):
  - pre-commit: `biome check --write` on staged files (auto-stages fixes) + `pnpm typecheck` for `*.{ts,tsx}` changes.
  - commit-msg: commitlint with `@commitlint/config-conventional` — commits must be Conventional Commits (`feat:`, `fix:`, `chore:`, etc.).
  - pre-push: `pnpm exec knip`. If knip blocks a push, fix the unused export/dep rather than working around it.
- **Knip** (`knip.json`) — entry points are configured per workspace; `infrastructure/**` is ignored. Storybook is enabled for `apps/auth`.

## Tailwind / CSS

Single source of truth is `packages/ui/src/styles/globals.css`. Each app imports it (Next.js via `app/layout.tsx`, Vite apps via `src/styles.css` or `main.tsx`). Tailwind v4 (`@tailwindcss/postcss` for Next/Keycloak, `@tailwindcss/vite` for admin). Theme tokens (CSS variables, dark mode) are defined there and consumed by every component in `@metronome/ui`.

## Conventions worth knowing

- Imports of UI components use the package path `@metronome/ui/components/<file>`, not relative paths into the package. The `exports` map in `packages/ui/package.json` is the contract.
- TypeScript is strict everywhere, with `noUncheckedIndexedAccess: true` in the base preset (Vite preset turns it off — see `packages/ts-cfg/vite.json`).
- Theme toggle: pressing `d` toggles dark mode in both web apps (see `components/theme-provider.tsx`).
- Do not commit anything under `infrastructure/keycloak/` — it's a downloaded server distribution, gitignored apart from `docker-compose.yml`.
